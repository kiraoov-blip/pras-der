# 시뮬레이터 접근 승인 (사번·소속·이름 + 관리자 카카오톡 코드)

잠긴 시뮬레이터를 열면 아래 순서로 들어갑니다.

1. 사번(8자리)·소속·이름을 입력하고 **접속 코드 요청**을 누릅니다.
2. 관리자 카카오톡 「나와의 채팅」에 「홍길동 · 요금분석팀 · 사번 12345678 · 대상 CARE-Jeju · 코드 482913」이 옵니다.
3. 관리자가 요청자를 확인하고 코드를 직접 전달합니다.
4. 요청자가 코드를 입력하면 입장합니다. 그 브라우저에서는 30일 동안 다시 묻지 않고, 잠긴 시뮬레이터 모두에 들어갈 수 있습니다.

관리자는 잠금 화면 아래 **관리자 로그인**을 눌러 사번과 비밀번호로 들어갑니다. 접속 요청·승인·접속 기록은 구글 시트에 쌓입니다.

| 파일 | 역할 |
|---|---|
| `auth/gate.js` | 잠금 화면. 배포할 때 잠글 시뮬레이터의 모든 HTML에 자동으로 들어갑니다 |
| `auth/apps-script/Code.gs` | 승인 서버(구글 Apps Script). 저장소에는 보관용으로 두고, 실제로는 Apps Script 편집기에 붙여 넣어 씁니다 |
| `.github/workflows/deploy-pages.yml` | `LOCKED` 목록의 폴더에 잠금 화면을 넣습니다 |
| `hub/index.html` | 잠긴 카드에 「승인 필요」를 표시합니다(`data-locked`) |

## 유포 방지 (관리자와 '워터마크 제외' 대상은 표시 제외)

승인받은 사람이 자료를 밖으로 퍼뜨리기 어렵게 하고, 퍼졌을 때 누가 가져갔는지 알 수 있게 합니다.

| 수단 | 내용 |
|---|---|
| 화면 워터마크 | 시뮬레이터 화면 전체에 「이름 · 사번 · 날짜」가 옅게 비스듬히 반복됩니다. 화면 캡처·사진·인쇄물에 그대로 찍히고, 개발자 도구로 지워도 다시 생깁니다 |
| 그림(PNG) 저장 | 저장한 그림에 같은 워터마크와 오른쪽 위 「저장: 시뮬레이터 · 이름 · 사번 · 날짜」가 들어갑니다(html2canvas를 쓰는 IEA 등) |
| 엑셀 저장 | 내려받은 엑셀 파일에 「이용자」 시트(이름·사번·날짜·외부 전달 금지 안내)가 추가됩니다(SheetJS를 쓰는 IEA 등) |
| 복사 | 30자 이상 복사하면 붙여 넣은 내용 끝에 「— 시뮬레이터 · 이름 · 사번 · 날짜 복사 · 외부 전달 금지」가 붙습니다 |
| 기록 | 내려받기(파일 이름)·복사(글자 수)·인쇄가 시트 「접속기록」에 `내려받기`/`복사`/`인쇄`로 남습니다 |
| 검색엔진 차단 | 잠긴 페이지에 `noindex`를 넣어 검색 결과에 내용이 나오지 않게 합니다 |

**사람별 예외:** 시트 「사용자」의 **워터마크 제외**(I열)에 체크하면, 그 사람은 다음에 페이지를 열 때부터 아래 표시가 모두 빠집니다. 체크박스 대신 `O`·`예`·`Y`를 써도 됩니다.
- 빠지는 것: 화면 워터마크, 그림 워터마크, 엑셀 「이용자」 시트, 복사 문구
- 그대로 남는 것: 내려받기·복사·인쇄 기록
- 반영 시간: 체크를 풀면 1분 안에 다시 표시됩니다.

시뮬레이터별 적용 범위:
- IEA: 모든 수단이 적용됩니다.
- PRAS-TOU: CSV 내려받기가 기록되고, 화면 워터마크·복사·인쇄도 적용됩니다.
- PRAS-DER·CARE-Jeju: 저장 기능이 없어 화면 워터마크·복사·인쇄만 해당합니다.

CSV 파일 자체에는 표시를 넣지 않고 기록만 남깁니다.

> 화면을 가리는 방식(A 수준)입니다. 일반 사용자는 들어오지 못하지만, 페이지 파일과 데이터는 공개 저장소에 그대로 있습니다. 그래서 개발자 도구를 쓰거나 GitHub에서 직접 보는 사람까지 막지는 못합니다.

## 처음 설정 (한 번만)

### 1. 구글 시트와 Apps Script 만들기

1. 구글 드라이브에서 새 스프레드시트를 만듭니다(예: 「시뮬레이터 접근 관리」).
2. 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
3. 기본으로 있는 `Code.gs` 내용을 모두 지우고 `auth/apps-script/Code.gs`를 통째로 붙여 넣은 뒤 저장(💾)합니다.
4. 위쪽 함수 선택에서 **`setup`**을 고르고 **실행**합니다. 권한 확인 창이 뜨면 본인 계정으로 허용합니다.
   - 「확인되지 않은 앱」이 나오면 **고급 → (프로젝트 이름)(으)로 이동**을 누릅니다.
   - 시트에 「사용자」, 「접속기록」 탭이 생깁니다.
   - 「사용자」 탭 I열은 「워터마크 제외」 체크박스 칸입니다. 예전 버전으로 이미 `setup`을 실행했다면 한 번 더 실행하면 이 칸이 생깁니다.

### 2. 관리자 비밀번호 저장

1. Apps Script 왼쪽 ⚙️ **프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**를 누르고 아래 값을 넣은 뒤 저장합니다.

   | 속성 | 값 |
   |---|---|
   | `ADMIN_EMP_ID` | 관리자 사번 8자리 |
   | `ADMIN_PASSWORD` | 관리자 비밀번호(8자 이상) |
   | `KAKAO_REST_API_KEY` | 카카오 앱 REST API 키(전기요금 채널 20N과 같은 앱의 키를 써도 됩니다) |
   | `KAKAO_CLIENT_SECRET` | 카카오 앱에서 Client Secret을 쓰는 경우만 |

2. 함수 **`setupAdminPassword`**를 실행합니다.
   - 비밀번호는 해시값으로 바뀌어 저장되고, 원문(`ADMIN_PASSWORD`)은 스크립트 속성에서 자동으로 지워집니다.
   - 비밀번호를 바꿀 때도 `ADMIN_PASSWORD`를 다시 넣고 이 함수를 실행하면 됩니다.

### 3. 웹앱으로 배포

1. 오른쪽 위 **배포 → 새 배포 → 유형 선택(⚙️) → 웹 앱**을 고릅니다.
2. 아래처럼 설정하고 **배포**를 누릅니다.
   - **다음 사용자 인증 정보로 실행:** 나
   - **액세스 권한이 있는 사용자:** 모든 사용자
3. 나온 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사해 둡니다.

### 4. 카카오톡 연결 (나에게 보내기)

[카카오 개발자 콘솔](https://developers.kakao.com)에서 20N에 쓰던 앱(또는 새 앱)을 엽니다.

1. **카카오 로그인 → Redirect URI**에 3번에서 받은 웹 앱 URL을 **추가**합니다. 20N 주소는 그대로 둡니다.
   - 정확한 주소는 Apps Script에서 함수 `showKakaoRedirectUri`를 실행하면 실행 로그에 나옵니다.
2. **플랫폼 → Web → 사이트 도메인**에 `https://simulator-kepco.co.kr`을 추가합니다. 카카오 메시지의 「시뮬레이터 열기」 링크용입니다.
3. **동의항목**에서 「카카오톡 메시지 전송(talk_message)」이 켜져 있는지 확인합니다.
4. Apps Script에서 함수 **`showKakaoConnectUrl`**을 실행하고, 실행 로그에 나온 주소를 브라우저에서 엽니다. 카카오 동의를 마치면 「✅ 카카오톡이 연결되었습니다」가 뜹니다.
5. 함수 **`testKakao`**를 실행해 「나와의 채팅」에 테스트 메시지가 오는지 확인합니다.

### 5. 잠금 화면에 서버 주소 넣기

`auth/gate.js` 위쪽의 아래 줄에 3번의 웹 앱 URL을 넣습니다.

```js
var API = 'https://script.google.com/macros/s/…/exec';
```

### 6. 저장소에 올리기

`auth/gate.js`, `auth/apps-script/Code.gs`, `auth/README.md`, `hub/index.html`, `.github/workflows/deploy-pages.yml`을 올립니다. 배포가 끝나면 잠긴 시뮬레이터에서 잠금 화면이 보입니다.

### 7. (선택) 카카오 연결 끊김 미리 알림

카카오 연결(갱신 토큰)은 약 2개월마다 만료됩니다. 코드 요청이 자주 들어오면 쓰는 동안 자동으로 연장됩니다. 그래도 끊길 때를 대비하려면 아래 트리거를 걸어 두세요.

- 설정: Apps Script 왼쪽 ⏰ **트리거 → 트리거 추가** → 함수 `weeklyKakaoCheck`, 이벤트 소스 「시간 기반」 → 「주 단위」
- 효과: 만료 2주 전에 메일로 알려 줍니다.
- 이미 끊겼을 때: 코드 요청이 오면 카카오톡 대신 **이 스크립트 소유자의 구글 메일**로 코드가 갑니다. 코드가 사라지지는 않습니다.

## 평소 관리

| 하고 싶은 일 | 방법 |
|---|---|
| 누가 들어왔는지 보기 | 시트 「접속기록」(코드요청·승인·접속·관리자로그인·실패). 같은 사람·시뮬레이터·날짜의 접속은 하루 한 줄만 남습니다 |
| 특정 사람 워터마크 빼기 | 시트 「사용자」에서 그 사람의 **워터마크 제외**에 체크합니다. 기록은 계속 남습니다 |
| 특정 사람 막기 | 시트 「사용자」에서 그 사람의 **상태**를 `차단`으로 바꿉니다. 1분 안에 잠기고, 새 코드도 요청할 수 없습니다 |
| 승인만 취소(다시 요청은 가능) | 시트 「사용자」에서 그 사람의 행을 지웁니다 |
| 모두 다시 인증받게 하기 | Apps Script에서 `revokeAllTokens` 실행 |
| 잠글 시뮬레이터 바꾸기 | `deploy-pages.yml`의 `LOCKED: "pras tou care iea-price"`에서 폴더 이름을 넣거나 빼고, `hub/index.html`의 해당 카드에 `data-locked`를 붙이거나 뗍니다 |
| 이 브라우저에서 로그아웃 | 잠긴 시뮬레이터 주소 끝에 `?sg-logout`을 붙여 엽니다(예: `/care/?sg-logout`) |
| Code.gs 수정 후 반영 | **배포 → 배포 관리 → ✏️ 편집 → 버전: 새 버전 → 배포**. 주소가 그대로 유지됩니다(「새 배포」를 만들면 주소가 바뀝니다) |

**지금 설정값** (Code.gs 위쪽 `CFG`에서 바꿀 수 있습니다)

| 항목 | 값 |
|---|---|
| 코드 유효시간 | 24시간 |
| 코드 입력 | 5번 틀리면 무효 |
| 통행증 | 일반 사용자·관리자 모두 30일 |
| 코드 요청 한도 | 사번당 1시간 3번, 전체 1시간 30번 |
| 관리자 비밀번호 | 5번 틀리면 30분 잠금(잠기면 카카오로 알림) |
